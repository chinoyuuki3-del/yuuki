# FIELDLINK / フィールドリンク

現実の相手に端末を向け、位置・向き・高さで命中を判定するゲームのウェブ開発版。開始後の画面は発射・武器・アイテムなどの操作ボタンだけです。マップ・仮想戦闘画面・照準ビューはありません。Render Web Service 1台で画面配信と WebSocket 対戦を処理します。Sitesは使いません。

## 起動

Node.js 22以上で `npm ci`、`npm start`。既定のポートは3000、Renderでは `PORT` を使用し `0.0.0.0` にバインドします。`npm test` でゲームルールと2クライアントのサーバー統合テストを実行します。

## Render

- リポジトリ内の `fieldlink-render/` にこのフォルダーを置きます。
- サービス種別: Web Service / Node
- Build: `cd fieldlink-render && npm ci --omit=dev && npm test`
- Start: `node fieldlink-render/server.mjs`
- Health: `/health`
- 環境変数: `NODE_VERSION=22`, `GAME_SECRET` (十分長いランダムな値)
- 必要なら `PUBLIC_ORIGIN=https://自分のホスト名` を指定できます。
- 単一インスタンス用です。複数インスタンスへの拡張には共有状態ストアが必要です。

`GAME_SECRET` は保存データの署名に使います。ソースコードには含めず、Render環境変数で固定してください。省略時は起動ごとに変わるため、再起動後に保存データを復元できません。

## 遊べる機能

- 2人のオンラインルーム、双方の準備完了後の同時カウントダウン
- 水平方向・仰角を使う3次元レイ判定。5m先の相手にも前を向けば当たり、上を向けば外れる
- タブレットの親指用発射ボタン、左右表示設定、サイズ設定、タッチ移動・照準
- キーボード: 十字キー移動 / WASD照準 / R向きの読み上げ / Space発射 / 1〜6武器 / J上昇 / K下降 / M地雷 / Bボム / N強化地雷 / H回復 / Gシールド
- 無限ピストル、消費弾の5種類の購入銃、ゲーム内コインのショップ
- 標準地雷は無限（同時3個）、消耗ボム・強化地雷、復活アイテムと4秒シールド
- 落ちているアイテム、距離に応じた振動、方向の日本語音声案内（対応端末のみ）
- 本体方向センサーの許可・正面調整、端末の位置情報による移動
- 省エネ: 状態受信5Hz、操作送信5Hz。自分の爆発物・上昇を禁止し、相手の爆発物は有効
- QRまたは友達コードで申請し、相手の承認で相互登録。相手が一時的にオフラインでも10分間申請を預かり、接続時に再送します。サーバー再起動で未承認の申請は消えます。コード・招待リンクの貼り付けに対応し、双方から申請した場合も相互登録します
- 切断時の一時停止、再接続、1分の切断タイムアウト、署名付きブラウザー保存

NPC機能は廃止しました。対戦には友達の参加が必要です。PCキー操作は仮想座標・仮想方角を使うテスト用で、実際の相手の位置・方角には連動しません。本体操作とPCキー操作テストのルームは分離しています。

## 未対応・制限

1. **Bluetoothの端末同士の自動発見と近接スタートは未実装です。** Web Bluetoothの対応有無だけではスマホ同士の相互発見は実現できません。BLEの広告・GATTサーバー・近接確認を提供するネイティブアプリ連携が必要です。UIはその制限を明示し、QR接続テストとして動作します。Bluetoothが成功したふりはしません。
2. 位置情報はブラウザー/OSが情報源を決めます。Wi-Fiのみの指定はできません。位置情報の精度による開始・参加・移動の制限はありません。1m単位の現実の命中精度を保証するものではありません。実機による調整が必要です。位置は共通の緯度経度を基準とするメートル座標です。実移動は開始位置から各方向1km以内、特殊キー操作は28m四方です。
3. 本体の照準は地磁気基準の絶対方角と、構えの上下調整を使用します。相対方角しか取得できない端末では本体操作を開始せず、特殊キー操作を案内します。機種・画面向きごとの実機検証、GPS/磁気・加速度誤差の校正は未完了です。非対応時はキー・タッチ操作を案内します。
4. ジャンプはゲーム内の高さを1ずつ上げ、下降操作で下げる試作ルールです。最高4です。
5. 保存データはサーバー署名付きのブラウザーローカル保存です。ログイン・クラウド同期・アカウント回復はありません。サーバー再起動後の古い正当な保存データへの巻き戻し防止は、永続DB導入時の課題です。実際のお金は扱いません。
6. ゲーム状態はサーバーメモリーで管理します。再起動時に対戦ルームは終了します。無料Renderサービスにはスリープと起動待ちがあります。
7. 位置の真偽（GPS偽装）を保証する仕組みはありません。速度上限・弾薬・HP・購入・発射間隔はサーバーで制御します。

地理情報は参加している対戦ルーム内の移動にのみ使用し、ゲーム保存データやログに緯度経度を保存しません。公開ルーム一覧やチャットはありません。

## 暫定ルール

初期500コイン / 撃破80 / 勝利150 / 勝利者なしの参加30。制限時間150秒。対戦は生存者1人または時間で勝敗を決めます。銃の射程32m（パルス40m）、標的半径0.65m。数値は遊びながら調整できるよう `public/engine.mjs` に集約しました。

## 検証

`test/engine.test.mjs`: 高さと照準、5m射撃、遮蔽対象の優先、外れ弾の消費、連射間隔、復活とシールド、省エネ時の被爆、地雷上限、購入失敗、古い入力、アイテムの二重取得防止、報酬重複防止。

`test/server.test.mjs`: HTTP/健康確認、ソース非公開、QR生成、購入、双方の友達承認、2人ルーム、同時開始、所持していない武器の拒否、弾薬、切断時の停止、署名付き復帰と改ざん拒否。

### 位置情報の許可
準備画面の「① 位置情報を許可する」から端末の Geolocation API を直接呼び出します。サーバーの接続待ちは許可操作を妨げません。許可済みなら再確認なしで取得し、拒否・取得待ち・タイムアウトを別々に表示します。「許可画面が出ないとき」にサイト設定と外部ブラウザーの案内があります。サイトから端末の許可を強制変更することはできません。本体の向きは別のボタンで許可します。位置情報を取得できれば精度待ちで停止しません。許可・取得と本体の向きの準備は必要です。

### ルーム参加と拡張ストア
コード入力時のメインボタンは必ず参加処理に進み、新規作成はしません。ルーム招待リンク貼り付け・Enter参加に対応。サーバーでルームの操作方式を確認し、参加側を合わせます。本体操作の許可は利用者のボタン操作で取得します。距離確認は双方の測位誤差を考慮し、明らかに35mを超える場合に拒否します。同じルームへの再参加は既存ルームを壊さず表示を戻します。
ストアは15商品。3種類の購入銃、回復キット、ポケットシールド、4種類のまとめ買いを追加。回復は40HP・上限100、シールドは5秒で発射時に解除。既存の署名付きプロフィールは新しい所持品と弾薬欄を補完して引き継ぎます。
